# 空闲时间规划 Agent MVP 产品需求文档

**文档版本：** v1.0  
**产品阶段：** MVP  ̵  单城市或单校园试运行  
**文档状态：** 已冻结范围  
**目标平台：** 移动端优先网页  

## 1. 产品概述

### 1.1 产品定位

面向在校学生，以及因长期工作忙碌而突然拥有休闲时间、却不知道如何规划的人群，帮助用户将一段空闲时间转化为低决策成本、符合个人状态且可以执行的休闲计划。

产品不负责管理用户已有待办事项，核心是帮助用户回答：

> 现在有一段空闲时间，今天适合怎么过？

### 1.2 MVP 核心闭环

```text
进入网页
→ 选择兴趣方向
→ 填写空闲条件
→ 完成快速问卷
→ 生成结构化偏好
→ 从审核任务库筛选候选任务
→ 生成任务组合和时间计划
→ 用户调整并确认
→ 执行任务并记录状态
→ 必要时调整计划
```

### 1.3 MVP 目标

1. 用户无需注册即可完成一次规划。
2. 用户默认通过 5 题快速问卷获得第一版计划。
3. 用户可以选择 30 题深度问卷获得更精细的结果。
4. 系统能够根据时间、预算、出行和同行条件筛选任务。
5. 推荐结果覆盖用户选择的兴趣方向。
6. 用户可以修改任务时间、替换任务、跳过任务和添加自定义任务。
7. 系统能够记录任务执行状态，并支持重新排程。

## 2. 目标用户与使用场景

### 2.1 目标用户

- 在校学生：周末、假期或课程间隙拥有半天到一天的空闲时间。
- 长期工作忙碌者：在调休、周末或临时空闲时不知道如何安排。
- 临时获得空闲时间的人：只想快速获得一份不需要反复思考的计划。

### 2.2 MVP 重点场景

| 场景 | 用户需求 |
|---|---|
| 突然获得半天休息时间 | 快速生成一份可执行安排 |
| 周末不知道做什么 | 获得多方向任务组合 |
| 工作后精力不足 | 避免高压力活动，优先恢复型任务 |
| 想独处但不想完全躺平 | 获得低社交成本的轻量任务 |
| 临时改变想法 | 能够替换、跳过或重新安排任务 |

## 3. MVP 范围

### 3.1 纳入范围

- 匿名 Session
- 兴趣方向选择
- 前置条件分步收集
- 5 题快速问卷
- 30 题深度问卷
- 四级同意度量表
- 人工审核的通用任务库
- 规则版用户画像
- 规则版任务推荐 Agent
- 轻松、平衡、充实三种计划密度
- 任务时间排程
- 用户自定义任务
- 任务开始、完成、跳过、超时状态
- 任务提醒的页面内提示
- 重新排程、替换任务、今天先不做
- 网页展示最终计划
- 任务满意度和原因标签反馈

### 3.2 明确不纳入 MVP

以下能力不得作为 MVP 的交付阻塞项：

- 实时地图、商户和活动 API
- 真实地点、价格、营业时间和距离查询
- 活动预约、购票和支付
- 邮件发送
- PDF 自动生成和下载
- 双向日历同步
- 登录、账号体系和历史计划
- 浏览器推送通知
- 多城市和大规模任务库
- Agent 自主联网搜索
- Agent 自主虚构地点、价格或活动事实

### 3.3 MVP 数据边界

- 首期任务来源为人工审核的通用任务库。
- 城市或校园字段可以被用户填写，但不用于实时地点检索。
- 用户未填写城市或校园时，只返回通用居家或低地点依赖任务。
- 所有匿名数据仅服务于当前规划会话，支持用户主动删除。

## 4. 核心用户流程

### 4.1 首次规划流程

1. 用户进入首页。
2. 系统创建匿名会话。
3. 用户选择一个或多个兴趣方向。
4. 用户填写空闲时长、预算、城市或校园、居家/外出、独处/结伴等条件。
5. 系统推荐快速版问卷，并允许切换至深度版。
6. 用户完成 5 题或 30 题问卷。
7. 系统保存答案并生成结构化偏好画像。
8. 系统筛选并排序候选任务。
9. 系统生成任务组合和三档计划密度。
10. 用户选择或调整计划。
11. 用户可修改任务开始时间和持续时间，也可添加自定义任务。
12. 用户确认计划。
13. 用户在任务时间内开始、完成或跳过任务。
14. 系统根据状态提供完成反馈或调整入口。

### 4.2 中途退出流程

- 用户每次完成选择或回答后，系统自动保存当前进度。
- 用户刷新、关闭页面或重新进入时，系统恢复当前会话。
- 用户可以继续当前流程，也可以清空本次数据重新开始。

### 4.3 计划调整流程

```text
任务未开始、被跳过或超时
→ 显示“计划需要调整”
→ 选择立即重排 / 换一个任务 / 今天先不做
→ 生成新的计划草稿
→ 保留已完成任务
→ 用户确认新计划
```

## 5. 功能需求

### 5.1 Session 会话管理

**目标：** 让用户无需注册即可完成一次规划，并支持进度恢复。

**要求：**

- 首次进入网页时创建匿名会话。
- 会话保存兴趣方向、前置条件、问卷模式、答案、候选任务和计划草稿。
- 会话必须有有效期。
- 前端使用版本化本地存储保存临时草稿。
- 用户可以删除本次会话数据。
- MVP 不要求登录和跨设备同步。

**验收标准：**

- 新用户可以直接开始，不被注册页阻断。
- 刷新页面后能够恢复已完成的步骤。
- 清空操作后不得继续展示旧答案和旧计划。

### 5.2 兴趣方向选择

MVP 使用以下五个方向：

| 方向 | 用户可理解的表达 |
|---|---|
| 活力充电 | 运动、走动和恢复身体活力 |
| 松弛疗愈 | 放松、休息和缓解压力 |
| 社交连接 | 和朋友、同学或家人相处 |
| 乐享探索 | 吃喝、娱乐和轻度探索 |
| 自我成长 | 阅读、学习和兴趣提升 |

**要求：**

- 用户至少选择一个方向。
- 最多选择五个方向。
- 支持调整方向优先级。
- 支持选择“今天只想休息”。
- 选择“今天只想休息”后，默认降低高强度运动、强社交和高消费任务的优先级。

### 5.3 前置条件收集

前置条件采用分步方式收集，全部使用按钮、单选或多选控件。

#### 5.3.1 空闲时长

选项：

- 1 小时以内
- 1-3 小时
- 半天
- 全天

#### 5.3.2 预算

选项：

- 0 元
- 0-50 元
- 50-150 元
- 150 元以上

#### 5.3.3 地点和范围

选项：

- 居家
- 校园或小区附近
- 城市内

城市或校园名称为选填项。MVP 仅用于任务场景描述和后续数据统计，不触发实时地点查询。

#### 5.3.4 同行方式

选项：

- 独处
- 结伴
- 都可以

#### 5.3.5 节奏偏好

选项：

- 轻松恢复
- 平衡安排
- 充实利用

### 5.4 问卷模块

#### 5.4.1 问卷模式

| 模式 | 题数 | 默认用途 |
|---|---:|---|
| 快速版 | 5 题 | 默认入口，快速生成基础计划 |
| 深度版 | 30 题 | 用户主动选择，获得更精细画像 |

#### 5.4.2 量表选项

统一使用四级选项：

```text
非常同意
比较同意
不太同意
完全不同意
```

对应分值为 4、3、2、1。反向题必须在题库中明确标记反向计分。

#### 5.4.3 交互要求

- 单题展示。
- 显示已答题数、总题数和预计剩余时间。
- 支持上一题回看和修改。
- 支持跳过当前题。
- 支持复制上一题答案。
- 每次作答后自动保存。
- 快速版预计 1 分钟完成，深度版预计 3 分钟完成。
- 每完成 10 题显示一次轻量进度提示。

#### 5.4.4 题目筛选

- 根据居家/外出条件过滤不匹配题目。
- 根据独处/结伴条件调整社交相关题目比例。
- 根据学生或职场身份选择不同场景题。
- 深度问卷按兴趣方向优先级分配题量。
- 题目不足时只能使用已审核的同维度通用题补充。

### 5.5 用户画像模块

系统将问卷结果转换为结构化画像，不直接向用户展示复杂分数。

画像至少包含：

- 活力需求
- 恢复需求
- 社交偏好
- 探索偏好
- 成长偏好
- 预算偏好
- 出行偏好
- 同行偏好
- 画像置信度

MVP 使用确定性规则计算画像。大模型不得自行修改基础分数。

### 5.6 任务库模块

#### 5.6.1 任务来源

- 人工审核的通用任务库。
- 用户自定义任务单独存储，不修改公共任务库。

#### 5.6.2 任务字段

- 任务 ID
- 任务名称
- 任务描述
- 兴趣方向
- 预计时长
- 预算等级
- 居家/外出方式
- 独处/结伴方式
- 适用精力状态
- 适用身份
- 休息优先标记
- 审核状态
- 任务版本

#### 5.6.3 任务约束

- 任务必须经过审核后才能被推荐。
- 不能使用未经验证的实时商户信息。
- 任务不能违反用户的预算、时长、出行和同行条件。
- 没有城市或校园数据时，优先推荐居家或通用任务。

### 5.7 推荐模块与 Agent

#### 5.7.1 推荐流程

```text
硬约束过滤
→ 偏好匹配排序
→ 兴趣方向覆盖检查
→ 任务多样性检查
→ 生成推荐理由
→ 输出候选任务
```

#### 5.7.2 Agent MVP 定位

MVP 中 Agent 使用规则或受控模板实现，职责为：

- 根据结构化画像理解用户当前状态。
- 从已筛选任务中组合任务。
- 解释任务匹配理由。
- 生成不同计划密度的任务顺序。
- 提供替换任务建议。

Agent 不得：

- 虚构地点、价格、营业时间或活动事实。
- 突破预算、时间、出行和同行约束。
- 推荐任务库之外的真实活动。
- 直接修改用户画像基础分数。

#### 5.7.3 推荐结果

每次推荐至少返回：

- 候选任务列表。
- 每个任务的匹配理由。
- 用户选择方向的覆盖情况。
- 轻松、平衡、充实三套计划建议。
- 未能满足的条件和原因。

如果可用任务少于预期，返回实际可用数量，不强行补足不符合条件的任务。

### 5.8 计划排程模块

#### 5.8.1 排程规则

- 计划任务总时长不得超过用户可用时间。
- 任务之间不得重叠。
- 至少保留一个低压力休息块。
- 任务预算总和不得超过预算上限。
- 居家用户不得安排需要外出的任务。
- 独处用户不得默认安排强制社交任务。
- 计划密度影响任务数量和休息间隔。

#### 5.8.2 用户调整

用户可以：

- 修改任务开始时间。
- 修改任务持续时间。
- 替换任务。
- 删除任务。
- 重新排程。
- 添加自定义任务。

系统遇到时间冲突时必须阻止保存，并提示可用时间范围。

#### 5.8.3 计划版本

- 初次生成计划为草稿版本。
- 用户确认后生成确认版本。
- 重新排程生成新版本，不覆盖旧版本。
- 已完成任务在新版本中必须保留。

### 5.9 自定义任务

用户可添加自定义任务，字段包括：

- 任务名称
- 任务方向
- 开始时间
- 持续时间
- 可选原因标签

自定义任务必须经过同样的时间冲突和空闲时间校验。

### 5.10 任务执行模块

#### 5.10.1 状态

```text
待开始 pending
进行中 active
已完成 completed
已跳过 skipped
未执行 missed
已超时 overdue
计划需要调整 needs_adjustment
```

#### 5.10.2 规则

- 用户到达开始时间后可以点击开始。
- 开始后可以点击完成。
- 用户可以主动跳过任务。
- 到开始时间后仍未开始，系统内部记录为 `missed`。
- 开始后超过结束时间仍未完成，系统内部记录为 `overdue`。
- 用户界面统一显示为“计划需要调整”。
- 计划调整不能覆盖已完成任务。

#### 5.10.3 页面提醒

- 默认在任务开始前 10 分钟显示页面内提醒。
- 用户可选择 5、10、15 或 30 分钟。
- 浏览器通知属于受控增强功能，MVP 只保留页面内提醒。

### 5.11 反馈模块

任务完成后允许用户：

- 选择 1-5 分满意度。
- 选择可选原因标签。
- 不填写文字原因。

原因标签示例：

- 太累了
- 时间不合适
- 不感兴趣
- 预算不合适
- 环境不合适
- 比预期更喜欢

反馈用于后续规则优化，不作为当前计划生成的强制条件。

### 5.12 计划交付

MVP 只交付网页计划：

- 展示计划摘要。
- 展示任务时间线。
- 展示任务详情和匹配理由。
- 展示任务状态。
- 提供调整、替换和反馈入口。

PDF、邮件和日历写入在 MVP 中不实现，但接口设计应预留计划快照能力。

### 6.1 页面清单

1. 首页/会话入口
2. 兴趣方向选择页
3. 前置条件页
4. 问卷模式选择页
5. 单题问卷页
6. 推荐结果页

8. 任务执行页

10. 自定义任务弹窗
11. 反馈弹窗

### 6.2 必须提供的状态

每个页面必须考虑：

- 正常状态
- 加载状态
- 保存状态
- 无数据状态
- 校验错误状态
- 推荐不足状态
- 网络中断状态
- 恢复草稿状态

## 7. 异常处理

| 异常 | 产品处理 |
|---|---|
| 问卷题库不足 | 使用同维度审核题补充 |
| 无匹配任务 | 展示限制原因，提供低压力通用任务 |
| 推荐输出不合规 | 使用规则结果降级，不展示错误信息 |
| 网络中断 | 保留本地答案，恢复后继续 |
| 任务时间冲突 | 阻止保存，展示可用时间 |
| 任务未开始或超时 | 展示“计划需要调整” |
| 用户中途退出 | 下次进入恢复当前进度 |
| 数据清空 | 删除本次会话和本地草稿 |

## 9. 验收标准

### 9.1 核心流程

- 用户可以选择 1-5 个兴趣方向。
- 用户可以完成前置条件填写。
- 用户可以在快速版和深度版之间选择。
- 快速版包含 5 道题，深度版包含 30 道题。
- 问卷使用统一四级选项。
- 刷新后能够恢复已保存答案。
- 系统可以生成至少一套符合硬约束的计划。
- 推荐任务覆盖用户选择的兴趣方向；无法覆盖时必须明确提示。
- 用户可以调整任务并重新生成有效排程。
- 用户可以添加自定义任务。
- 系统可以记录开始、完成、跳过和超时状态。
- 已完成任务不会在重排时被覆盖。
- 用户能够在网页查看完整计划。

### 9.2 约束校验

- 推荐任务不超过预算上限。
- 推荐任务总时长不超过可用时间。
- 任务之间不存在时间重叠。
- 自定义任务不能突破可用时间窗口。
- 居家条件不会生成必须外出的任务。
- Agent 不输出任务库之外的真实地点、价格或活动事实。

### 9.3 体验要求

- 默认路径以快速问卷为主，不强制用户完成 30 题。
- 问卷中途退出后无需从头开始。
- 异常状态有明确的下一步操作。
- 用户不会看到“乱填”“失败”等带有惩罚性的主提示。
- 任务未执行时，系统统一使用“计划需要调整”。

## 10. MVP 技术实现边界

### 10.1 推荐实现

- 前端：移动端优先网页。
- 后端：模块化单体 API。
- 数据库：保存任务库、会话、问卷、画像、计划和执行事件。
- 推荐：规则引擎优先，Agent 接口预留。
- 任务来源：本地审核任务库。
- 临时恢复：版本化本地存储。
- 外部数据：MVP 不依赖实时 API。

### 10.2 模块边界

```text
Session Module       管理会话和草稿
Questionnaire Module 管理题目和答案
Profile Module       计算结构化画像
Task Repository      提供审核任务
Recommendation       筛选并组合任务
Scheduling            生成时间计划
Execution             跟踪任务状态
Feedback              收集用户反馈
Delivery               展示网页计划
```

## 11. 版本排期建议

### Phase 0：产品和数据准备

- 冻结 PRD。
- 完成页面流程和交互稿。
- 建立第一版任务库和题库。
- 确定画像字段、任务字段和计划状态。

### Phase 1：核心闭环

- 完成 Session、问卷、画像和任务库。
- 完成推荐、排程和网页结果页。
- 完成基础测试和异常处理。

### Phase 2：执行闭环

- 完成自定义任务。
- 完成开始、完成、跳过和超时状态。
- 完成重新排程和反馈。
- 完成埋点和内部测试。

### Phase 3：小范围灰度

- 在一个校园或一个城市试运行。
- 使用通用任务，不接实时 API。
- 邀请种子用户完成真实任务。
- 根据问卷完成率、计划确认率和任务完成率进行迭代。

## 12. 后续版本方向

仅在 MVP 核心闭环稳定后考虑：

1. PDF 下载和邮件发送。
2. 浏览器通知。
3. 历史计划和偏好复用。
4. 日历读取与写入。
5. 地图、商户和活动 Provider。
6. 多城市和校园任务库。
7. 大模型 Agent 的自然语言交互。

## 13. MVP 成功定义

MVP 达到以下条件即可进入小范围灰度：

> 新用户无需注册，能够在几分钟内完成兴趣选择、前置条件填写和问卷，并获得一份符合自身时间与预算的计划；用户可以修改计划、执行至少一个任务，并在任务未完成时获得清晰的调整入口。

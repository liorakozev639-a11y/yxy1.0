# 空闲时间规划 Agent 产品计划

## 1. 产品概述

### 1.1 产品定位

面向在校学生，以及因长期工作繁忙而在突然获得休闲时间时不知如何规划的职场人，提供半天、周末或临时空闲时段的规划网页 Agent。产品的核心定位是：**不是帮用户管理已有任务，而是在用户突然拥有空闲时间时，帮助用户决定今天适合怎么过。** 用户默认进入 5 题速测，也可主动选择 30 题深测；系统据此推荐可执行任务并生成半天计划。结果支持在线查看、下载 PDF 与单次授权发送至邮箱。

### 1.2 要解决的问题

当用户拥有半天或一天空闲时间时，常常在休息、社交、娱乐和提升自己之间摇摆，最终要么没有安排，要么排得过满。长期工作繁忙的职场人尤其容易在突然拥有空闲时间后因决策疲劳而无从规划。本产品将模糊的“想做点什么”转化为符合时间、预算和精力约束的可调整计划。

### 1.3 MVP 目标

- 在一次网页会话内完成从偏好选择到计划交付的完整闭环。
- 以 5 题速测作为默认主路径，降低首次使用门槛；通过 30 题深测满足高个性化需求。
- 把问卷完成率、单题耗时、恢复率和异常作答率纳入核心体验指标。
- 首期优先建设一个城市或校园的本地审核任务库，再逐步接入实时地图、活动和商户数据，保证推荐可用、可解释、可审核。
- 让用户在默认计划基础上保有修改权，而不是被动接受 Agent 的安排。
- 允许用户明确选择“今天只想休息”，推荐睡眠、发呆、听音乐、散步和无目标阅读等低压力任务，避免把休闲变成新的待办压力。

## 2. 用户与使用场景

### 2.1 目标用户

- 在校学生：主要在周末或假期拥有半天到一天的可支配时间。
- 长期工作繁忙的职场人：在周末、调休、年假或临时获得半天到一天休闲时间后，需要快速获得低决策负担的安排。

### 2.2 核心场景

用户希望在不牺牲休息的前提下，得到一份兼顾个人偏好和现实条件的半天空闲安排；计划应包含少量固定时间段日程、充分留白，以及可以自由替换的任务清单。

## 3. 兴趣方向与前置条件

### 3.1 五个兴趣方向

| 方向 | 含义 | 示例活动 |
| --- | --- | --- |
| 活力充电 | 运动、户外与身体恢复 | 跑步、骑行、补觉、拉伸 |
| 松弛疗愈 | 减压、安静休息与情绪恢复 | 阅读、冥想、漫步、独处 |
| 社交连接 | 与朋友、同学、社团或家人的互动 | 聚餐、桌游、社团活动 |
| 乐享探索 | 美食、观影、游戏与校园/城市探索 | 看电影、逛展、探店 |
| 自我成长 | 学习、创作、整理与复盘 | 学习新技能、写作、整理资料 |

用户可多选方向，并对所选方向排序以表达优先级。

### 3.2 前置条件表单

用户选择方向后填写：

- 身份与近期学习/工作状态：在校学生或职场人；节奏平稳、忙碌/加班中、休假或调休。
- 可用日期与时长：今天、本周末或下个休息日；优先支持 1 至 3 小时和半天，全天作为后续扩展。
- 预算区间。
- 所在城市或校园。
- 活动方式：居家完成、附近出门或自由出门。
- 同行偏好：独处、结伴或都可以。
- 安排节奏：轻松留白、张弛平衡或充实一点。

这些条件在问卷前收集，用于后续题目筛选、任务检索和排程校验。

## 4. 用户流程

### 4.1 首屏与前置分流

1. 打开网页，首屏只展示五个兴趣方向供用户多选和排序，不出现文字输入框。
2. 采用轻量分步条件收集：
   - 第一步：可用时长（1 小时、3 小时、半天）与出行范围（居家、就近、全城）。
   - 第二步：预算档位与同行偏好。
   - 第三步：身份、学习/工作状态、所在城市或校园、节奏偏好，均为可折叠选填项。
3. 城市或校园为空时，系统只推荐居家或通用任务；学习/工作状态为空时使用通用权重，不阻断流程。
4. 完成方向和基础条件后，默认进入 5 题速测；用户可以主动切换到 30 题深测，不强制进入深测。

### 4.2 双问卷模式

**5 题速测**：默认入口，适用于临时快速规划或不愿填写长问卷的用户。覆盖五个兴趣方向各 1 道核心题，输出一份半日基础计划和 10 个候选任务，提供简短匹配理由。

**30 题深测**：适用于追求高匹配度的用户。输出完整偏好画像、每项任务匹配理由、多套排程方案与精细调整权限。用户可在深测过程中随时切换速测，不因中途退出而返工。

场景默认推荐：1 至 3 小时、半天和临时空闲默认推荐速测；用户想深入探索或多次使用后，再推荐深测。深测始终保留切换入口，但不作为首屏主路径。

### 4.3 结果交付

1. 系统根据问卷答案和前置条件生成 10 个候选任务。
2. 系统生成默认时间段计划；用户可删除、替换候选任务或重新排程。
3. 用户确认后，在线查看、下载 PDF 或单次授权发送到邮箱。

问卷页面每次只显示一题，固定底部操作区，提供进度、预计剩余时间、上一步、跳过和恢复能力。候选任务页展示方向、时长、预算、地点、活动方式、同行条件和匹配理由。最终计划页同时展示时间段日程与可调整任务清单。

### 4.4 任务执行闭环

用户选中任务后，可以自行设置开始时间和持续时间。计划密度由用户选择“轻松留白、张弛平衡、充实一点”三档决定，分别控制默认任务数量、休息时长和时间利用率。

每个任务卡提供“开始、完成、跳过、换一个”四个操作，并提供可选倒计时。用户自定义任务时填写任务名称、预计时长、所属方向、预算、活动方式和同行偏好。

任务状态包括：待开始、进行中、已完成、需要调整、已放弃。开始时间前默认提前 10 分钟提醒，用户可调整为 5、15 或 30 分钟。到达开始时间仍未启动，或启动后超过结束时间未完成，系统内部记录为未执行或超时，但用户界面统一显示为“计划需要调整”，并通过页面内提醒通知；用户授权后可追加浏览器通知。

需要调整的任务提供“立即重排、换一个任务、今天先不做”三个选项，默认突出立即重排。用户手动设置时间造成冲突时，系统阻止保存，提示最近可用时间并提供一键调整。

任务完成后，用户只需标记完成，并可选择 1 至 5 分满意度；原因标签为可选填写。反馈用于优化后续画像、任务排序和计划密度。

## 5. 问卷规则

### 5.1 基本规则

- 问卷分为 5 题速测和 30 题深测两种模式，用户可主动切换。
- 深测题目统一使用四级迫选量表：`非常同意｜比较同意｜不太同意｜完全不同意`。
- 默认分值从 4 分到 1 分依次递减；如题目为反向表述，题目记录中必须标记反向计分。
- 题干统一使用简短单句，每题只描述一种行为或偏好，不使用双重条件。
- 题目来自审核后的结构化题库，不由模型临时生成。
- 每道题具有问卷模式、方向标签、衡量维度、适用条件、选项评分权重和反向计分标记。
- 任务单独标记“休息优先”，用于用户选择“今天只想休息”时优先返回。

### 5.2 题目分配

**速测模式**：固定 5 题，覆盖五个兴趣方向各 1 道核心题；用户已选方向用于调整权重，未选方向只保留粗粒度基线，不影响用户主流程。

**深测模式**：固定 30 题，并按方向优先级分配，而不是简单平均。优先级最高的方向获得最多题目，最低优先级方向获得最少题目；默认参考分配如下：

| 已选方向数 | 深测题目分配 |
| --- | --- |
| 1 | 30 |
| 2 | 18 / 12 |
| 3 | 14 / 10 / 6 |
| 4 | 10 / 8 / 7 / 5 |
| 5 | 8 / 7 / 6 / 5 / 4 |

当高优先级方向题库不足时，系统按同一衡量维度补充相邻题；题库仍不足时使用审核过的通用题，不要求用户重新选择方向。

### 5.3 智能抽题与偏好画像

前置条件联动题库筛选：选择居家时剔除大部分户外题；选择独处优先时减少社交题；学生优先抽取校园场景题，职场人优先抽取下班、调休和恢复精力场景题。系统优先筛掉与现实约束不匹配的题目，再按方向优先级、画像维度和历史作答情况抽题。

深测中反向计分题不超过总题量的 1/5。量表题的选项分数汇总为结构化字段，包括：精力水平、恢复需求、社交偏好、消费意愿、出行半径、学习/放松倾向和方向优先级。基础计分由规则服务完成，Agent 只消费画像结果，不承担不可验证的基础打分。

### 5.4 作答减负与恢复

- 使用单页单题布局，选项固定在底部，移动端采用大尺寸点击区域。
- 顶部显示“已答/总题数”和预计剩余时间：速测约 1 分钟，深测约 3 分钟。
- 支持上一题回看修改、复制上一题答案和跳过当前题；跳过题使用中性默认分，不阻断流程。
- 每次作答立即写入 `localStorage`；刷新、切后台、关闭页面后重进均自动恢复。
- 提供一键清空本次问卷数据，避免用户逐题清除。
- 每完成 10 题显示一次正向提示，例如“已完成 1/3，很快就能生成专属计划”。

### 5.5 问卷话术

产品统一使用“空闲偏好小调查”“几道小问题”等轻量表达，避免“性格测评”“必须认真作答”等增加心理压力的词语。进入问卷前明确告知成本：速测为 5 题、约 1 分钟；深测为 30 题、约 3 分钟。

## 6. 系统设计

### 6.1 模块划分

| 模块 | 职责 |
| --- | --- |
| 前端引导层 | 分步收集方向与条件；引导速测/深测选择；展示候选任务、执行状态和最终计划 |
| 问卷编排器 | 按模式、前置条件、方向优先级和画像缺口抽取题目 |
| 画像计算器 | 将问卷答案计算为结构化偏好画像 |
| 任务检索服务 | 首期以单城市或单校园的人工审核任务库为主，筛选满足时间、预算、地点和出行条件的任务；实时地图/活动/商户 API 作为增强数据源 |
| Agent 推荐器 | 按画像和约束挑选 10 个任务，给出匹配理由与替换建议 |
| 排程引擎 | 首期生成无时间冲突、未超预算的 1 至 3 小时或半天时间表 |
| 执行状态服务 | 管理开始、完成、跳过、需要调整、重排和满意度反馈 |
| 日历同步服务 | 经用户确认后读取并写入外部日历，维护双向变更关系 |
| 通知服务 | 发送开始前提醒、计划调整提醒和重排提示 |
| 交付服务 | 将同一确认计划渲染为网页、PDF 与邮件内容 |

### 6.2 数据模型

**题目**：题目 ID、问卷模式、方向标签、短题干、四级量表选项、维度、选项权重、适用条件、反向计分标记、状态。

**任务**：任务 ID、方向标签、名称、描述、用户设定开始时间、预计持续时间、预算区间、室内外、是否需要同伴、地理范围、精力需求、准备事项、执行状态、状态。

**计划会话**：匿名会话 ID、已选方向及优先级、问卷模式、前置条件、问卷答案、已答进度、偏好画像、候选任务、确认计划、执行记录、满意度反馈、有效期。未注册用户的临时答案只保存在浏览器本地。

**邮件投递**：一次性投递 ID、计划快照、发送状态、失败原因、过期时间。邮箱地址仅用于当前投递，不写入长期用户档案。

### 6.3 Agent 边界

Agent 输入为结构化偏好画像、用户约束和已筛选任务集。输出固定为：偏好摘要、10 个候选任务、每项匹配理由、默认计划、调整建议和需要调整时的替代任务建议。

Agent 不得虚构地点、价格、开放时间或活动事实；只能从任务库返回任务或基于已有任务组合。最终输出进入展示层前必须通过规则校验。

### 6.4 排程规则

- 10 个候选任务必须覆盖全部已选方向。
- 默认计划的已排任务总时长不得超过用户可用时长。
- 任务预算总和不得超过预算上限。
- 出门与结伴约束必须满足。
- 任务之间预留必要的休息或通勤缓冲时间。
- 用户替换或删除任务后，可一键重新排程。
- 用户选择轻松、平衡或充实密度后，系统调整任务数量和休息缓冲。
- 用户自定义开始时间和持续时间后，系统必须阻止任务重叠、超出可用时间或违反日历已有安排。
- 任务未执行或超时后，重排只使用剩余可用时间，不自动覆盖用户已经完成的任务；用户界面不使用“失败”作为主要提示。
- 计划中至少保留一个低压力休息块；当用户选择“今天只想休息”时，默认不安排高强度运动、强社交或高消费活动。

## 7. 交付与隐私

最终计划提供三种一致的交付形式：

- 网页展示：可继续调整并重新排程。
- PDF 下载：生成计划快照，便于离线保存。
- 邮件发送：用户填写邮箱并主动勾选单次发送授权后投递。

匿名用户的问卷与条件仅在当前会话或浏览器本地保留；登录用户可在授权范围内保存历史计划、问卷结果和常用条件。计划生成后可匿名保留质量指标。页面提供“删除本次数据”入口。计划链接使用短时有效访问令牌；邮件失败时，用户仍可使用网页和 PDF，并可重新发送。

首期以人工审核任务库为唯一可靠来源，先在一个城市或校园内验证任务供给和推荐质量。地图、活动和商户 API 作为后续增强，仅用于搜索与推荐，不提供预约、购票或支付。用户默认手动填写城市或校园，也可以主动授权精确定位；实时数据不可用时继续使用审核任务库，并标注“通用建议”或数据时效性。

首版支持双向日历同步：经用户授权读取已有日历安排，避免生成冲突；用户确认最终计划后，一次性选择目标日历并写入全部任务。产品内删除或重排计划时，不自动删除已写入的日历事件，除非用户再次确认。

采用匿名优先、登录增强：无需注册即可完成问卷、生成计划和下载 PDF；用户主动登录后才保存历史计划、问卷结果和常用条件。日历读取、日历写入、精确定位和浏览器通知均需单独授权，并支持撤销权限。账号删除时同步删除历史问卷、计划和偏好数据。

## 8. 异常处理与质量控制

| 场景 | 处理方式 |
| --- | --- |
| 题库不足 | 按同一维度匹配审核过的通用题补足速测或深测，不要求用户返工 |
| 无匹配任务 | 优先返回审核过的低压力通用任务，再指出限制条件并建议放宽预算、出行或结伴偏好 |
| Agent 输出不合规 | 重新检索并生成；仍失败则降级为规则推荐 |
| 网络中断 | 保留当前会话答案，允许恢复问卷 |
| 邮件失败 | 展示失败原因，保留网页和 PDF，允许重试 |
| 连续同一选项或异常快答 | 不直接拦截；提供切换速测或只重答少量异常题的入口 |
| 中途退出 | 下次进入自动恢复已答题目和问卷模式 |
| 实时 API 不可用 | 降级到人工审核任务库，标注数据时效性；仍可生成通用计划 |
| 日历读取失败 | 使用用户手动填写的不可用时间，提示日历未同步 |
| 写入日历失败 | 保留网页计划和 PDF，不重复创建事件，允许用户重新授权后重试 |
| 用户任务时间冲突 | 阻止保存，提示最近可用时间并提供一键调整 |
| 任务未开始或超时 | 内部记录未执行或超时，用户界面显示“计划需要调整”，提供立即重排、换任务、今天先不做 |

系统不向用户展示“判定为乱填”等对抗性提示。对单题耗时低于 1 秒或连续 8 题相同选项的会话，仅标记低置信度并柔性处理：用户可直接切换 5 题速测，或只重新回答被标记的少量题目。所有结果在展示前校验：问卷模式与题数正确、量表选项完整、候选任务覆盖所有已选方向、最终计划不超时长且不超预算。

## 9. 验收标准

- 用户可选择 1 至 5 个方向，并在 5 题速测与 30 题深测之间自由选择。
- 深测每题使用统一的四级同意度选项：非常同意、比较同意、不太同意、完全不同意。
- 深测题目按方向优先级分配；速测覆盖五个兴趣方向各 1 题。
- 10 个候选任务均符合用户条件，且覆盖所有选中方向；线下任务显示地点、距离、价格和营业状态。
- 用户修改候选任务后可以重新生成有效排程。
- 用户可设置任务开始时间和持续时间，系统阻止冲突和超出可用时间的设置。
- 用户可以开始、完成、跳过、换一个任务；未执行或超时任务可以立即重排，且用户不会被强制重新安排。
- 用户可创建自定义任务，并将其加入当前计划。
- 任务开始前默认提前 10 分钟提醒，用户可调整提醒时间并授权浏览器通知。
- 最终计划经用户确认后可以一次性写入目标日历。
- 网页、PDF 和邮件中的已确认计划内容一致。
- 问卷支持自动保存、恢复、上一题修改、跳过和清空本次数据。
- 题库不足、无可用任务、网络中断、异常作答和邮件失败均有可理解的可操作提示。

## 10. 阶段规划

### MVP

首期聚焦一个城市或一个校园，以及半天以内的空闲规划。完成方向选择、分步条件收集、默认 5 题速测、可选 30 题深测、偏好画像、人工审核任务库、10 项候选任务、三档计划密度、任务执行状态、计划调整、自定义任务和网页展示；PDF、邮件、实时活动 API、双向日历同步作为受控增强能力接入。首版优先验证“速测 → 计划 → 执行 → 反馈”的完整闭环，而不是同时覆盖所有城市和所有活动类型。

### 第二阶段

增加实时地图/活动/商户 API、PDF 和邮件交付、双向日历同步、登录后的历史问卷复用、常用条件自动回填、基于历史作答的题目精简、收藏任务、个性化提醒、计划执行统计、校园单点登录（面向学生）与更多城市。

## 11. 成功指标

- 问卷完成率。
- 速测进入率、速测转深测率和各模式完成率。
- 首题到提交的平均耗时、单题平均耗时和中途恢复率。
- 跳过率、异常作答率和异常会话切换速测后的计划生成率。
- 计划生成成功率。
- 任务开始率、任务完成率、计划需要调整率、调整后继续执行率和重排成功率。
- “今天只想休息”入口使用率、低压力任务选择率和用户对休闲压力的反馈。
- 自定义任务使用率、日历写入成功率和日历冲突拦截率。
- 用户对默认计划的确认率与平均调整次数。
- PDF 下载率与邮件发送成功率。
- 用户对“计划可执行性”的满意度评分，以及完成任务后的 1 至 5 分反馈。

# 空闲时间规划 Agent 前端技术方案

> 状态：现有规则版前端与拟接入 AI 的目标方案合并稿。AI 生成功能尚未实现，本文描述目标交互与接口契约，不代表当前线上页面已切换。

## 1. 方案目标

围绕“突然拥有空闲时间后，不知道今天适合怎么过”的核心场景，前端采用低压力、分步式流程，优先完成半天以内的空闲规划闭环：

`兴趣方向 -> 前置条件 -> 5 题速测/30 题深测 -> 偏好画像解释 -> AI 候选任务与理由 -> 后端预算感知排程 -> 时间线 -> 执行调整`

当前规则版使用审核通用活动库。AI 目标版的任务内容全部由服务端模型生成并经过后端校验，不使用前端本地活动库，不因生成失败回退旧库；仍不依赖实时地图、商户或活动 API。

## 2. 页面架构

### 2.1 页面层级

1. 会话入口：创建或恢复会话，开始规划；不增加 AI 营销落地页。
2. 兴趣方向页：五个方向多选、优先级排序。
3. 前置条件页：时长、预算、出行、同行、节奏、只想休息；城市和工作状态选填。
4. 问卷页：默认 5 题速测，可切换 30 题深测；单题展示、自动保存、上一题、跳过、显式生成推荐。
5. 画像解释页：展示规则画像和可核对的用户输入依据，用户确认后生成计划。
6. 结果与计划页：展示最多 10 个 AI 候选及其第一步、理由、预算和负担；已安排子集进入时间线，未安排项显示原因。
7. 执行页：开始、完成、跳过、换一个、条件变化后调整剩余安排。
8. 总结页：网页展示当前计划与反馈；PDF 和邮件作为后续能力明确标注。

### 2.2 响应式策略

- 桌面端：左侧流程导航 + 右侧主内容区。
- 平板端：缩短侧栏，候选任务和时间线双栏排列。
- 移动端：侧栏隐藏，所有卡片和控件单列堆叠。
- 选项按钮最小点击高度建议 44px；避免横向滚动。
- 时间线在移动端保持“时间标签 + 任务块”结构，不改为不可读的宽表格。

## 3. 视觉系统

### 3.1 设计关键词

低压力、可执行、清晰、留白、轻量反馈。目标版沿用当前像素视觉，但优先保证任务信息可读和移动端可操作。

### 3.2 颜色

| 用途 | 建议颜色 |
| --- | --- |
| 主文字 | `#14213D` |
| 次要文字 | `#667085` |
| 主色 | `#2864DC` |
| 主色浅底 | `#EAF1FF` |
| 完成/休息 | `#16866B` |
| 需要调整 | `#C66B16` |
| 页面背景 | `#F4F7FB` |

颜色不单独承担状态含义；状态同时使用文字、图标或结构提示。

### 3.3 组件

- `AppShell`：品牌、进度、阶段导航、状态提示。
- `ChoiceGroup`：兴趣、预算、出行和同行条件。
- `QuestionCard`：单题、四级量表、进度、上一题和跳过。
- `ActivityCard`：标题、方向、时长、单项预算、第一步、推荐原因、前置条件入口和负担标签。
- `Timeline`：时间标签、任务块、休息块、状态标记。
- `GenerationStatus`：整理偏好、生成任务、校验与排程的真实阶段状态及重试入口。
- `BudgetSummary`：只汇总已排入时间线任务的预计花费，待安排候选不计入总额。
- `CustomTaskDialog`：名称、方向、开始时间、持续时间、预算、可选原因标签。
- `AdjustmentBanner`：计划需要调整、立即重排、换一个、今天先不做。
- `DeliveryActions`：网页确认、PDF/邮件测试状态。

状态更新采用单向流程：用户动作 -> API 请求 -> 服务端校验/保存 -> 根据返回的会话与计划版本重新渲染。`localStorage` 仅保存恢复会话所需的最小信息；AI 候选、预算、计划和执行状态以服务端为准，页面不直接修改 DOM 中的业务数据。

## 5. 逻辑模块边界

### 前端展示与 API 边界

- 前端保存兴趣、条件、问卷答题和画像查看状态，并调用后端接口；不得自行组装模型提示词或传模型密钥。
- `frontend/api.js` 负责会话恢复、`generatePlan()`、计划读取、替换、时间调整、重排、执行和反馈请求。
- 前端只格式化和展示后端返回的候选任务、两类理由、第一步、前置条件及时间线；不再执行任务库搜索、最终硬约束过滤或预算总额判定。
- 加入时间线、替换和调整时间时带计划版本，冲突后刷新最新计划并提示用户重新确认。

### `app.js`

负责：

- 阶段渲染和事件委托。
- 前置条件和问卷交互。
- 会话 ID 的本地恢复和损坏清理；服务器负责推荐任务与计划持久化。
- 画像解释、生成阶段、候选任务、时间线、预算摘要、自定义任务和执行卡片的渲染。
- PDF、邮件等后续能力的测试状态提示。

### `styles.css`

负责视觉系统、响应式布局、表单控件、时间线、提醒、弹窗和移动端适配。避免把业务状态写在 CSS 中；状态由语义 class 和文本共同表达。

## 6. 数据流

```mermaid
flowchart LR
    A[兴趣和条件] --> B[服务端会话]
    B --> C[问卷作答]
    C --> D[后端规则画像]
    D --> E[后端上下文与生成说明]
    E --> F[AI 生成候选及理由]
    F --> G[后端校验和持久化]
    G --> H[后端预算感知排程]
    H --> I[网页展示候选及时间线]
    I --> J[执行与反馈]
    J --> K[条件变化时仅重排剩余任务]
```

## 7. AI 任务展示契约

前端消费后端校验过的任务，而不是从旧活动库读取。每项至少展示 `id`、标题、分类、时长、单项预计花费、负担标签、`first_action` 和 `recommendation_reason`；详情展示 `prerequisites`、可选 `action_steps`、`generation_reason`、`evidence_refs` 与 `uncertainty_note`。理由须具体指向用户本次选择或作答，不展示模型内部推理，也不把未经校准的分数称为“可信度”。

十项推荐是候选池，时间线只包含后端实际安排的子集。候选总花费不等于计划总花费；前端预算摘要仅汇总已排任务。待安排候选显示自身预计花费与未安排原因。点击“加入时间线”或“换一个”后，使用后端新响应刷新预算、计划版本和原因，不在浏览器里自行扣加金额。前置条件包括必要物品、场地、预约、费用或他人配合；若没有条件则显示“无需额外准备”，不能隐藏非空条件。

## 8. 执行与容错

- 未选择兴趣方向：阻止进入前置条件。
- 跳过问卷题：记录为“未知”，不伪造中性或负面偏好；按后端允许的提交规则继续。
- 任务不足 10 条：显示实际数量和原因，不突破硬约束凑数。
- 模型超时、限流或无合格候选：保留已填写条件与作答，展示可理解的错误和重试；不显示旧任务库的静默回退结果。
- 自定义任务原因标签：空值合法。
- 时间重叠：阻止保存并给出最近可用时段。
- 未开始、超时或跳过：界面显示“计划需要调整”。
- 重排：前端保存新天气、精力、出行或可用时间，带 `current_context_version`、`expected_plan_version` 和剩余时间窗口请求后端。只移动尚未开始且未锁定任务；已完成、进行中、已跳过和用户锁定项保持原记录与反馈。锁定或进行中任务与新条件冲突时提示用户决定，不暗中改动。
- `localStorage`：只清理 Demo V2 自己的版本化 key，不触碰其他站点数据。
- PDF/邮件：首版显示“测试版暂未接入”，不伪造发送成功。

## 9. 后续技术演进

### 当前规则版

- 现有网页通过会话恢复和后端接口完成主要流程，推荐内容仍来自审核任务库。

### AI 目标版

- 维持现有像素视觉与分步流程，加入画像解释后的生成阶段、AI 任务字段展示、预算摘要和待安排原因。
- 任务由后端模型生成并校验；前端不进行本地任务库回退，刷新后从服务器恢复推荐与计划。
- “换一个”请求由后端排除本会话已出现的具体任务并生成新候选；纯重排不请求模型。
- 条件变化只调整剩余可移动任务，版本冲突时提示刷新后重试。

### 后续扩展

- 实时地点、日历、PDF、邮件和账号按需求接入；外部数据增加来源与新鲜度标记。

## 10. 验收指标

- 首屏到生成推荐的完成率。
- 5 题速测完成率和深测切换率。
- 推荐结果中硬约束违规数必须为 0。
- 每项推荐都显示具体第一步、真实前置条件和可核对的推荐原因；详情可查看生成理由与依据。
- 十项候选合计超预算但实际安排未超预算时不误报；加入、替换后预算摘要与后端一致。
- 条件变化后已完成、进行中和锁定项不移动，已有反馈不消失；纯重排不触发模型调用。
- 候选任务替换率和计划确认率。
- 自定义任务保存成功率。
- 计划需要调整后的继续执行率。
- 低压力任务和“今天只想休息”入口使用率。

# 用户测试指标使用说明

本文用于组织大学生用户测试，并使用项目内置的匿名遥测和管理员看板记录结果。测试指标只用于产品验证，不是用户画像、心理诊断或公开统计。

## 测试前准备

1. 启动 PostgreSQL，设置 `SESSION_DATABASE_URL`。
2. 为看板设置 `ADMIN_METRICS_USERNAME` 和 `ADMIN_METRICS_PASSWORD`。密码只放在当前终端、部署平台密钥或密码管理器中，不写入仓库。
3. 按 README 的启动方式运行后端和 `frontend` 静态服务器。
4. 确认主页可以访问，并在需要时确认 `http://127.0.0.1:5173/admin.html` 可以打开。数据库不可用时，不要开始正式测试。

## 匿名测试编号

### 生成规则

- 每名测试者分配一个独立编号，格式为 `student_` 加 3 到 6 位数字，例如 `student_001`、`student_042`。
- 测试批次使用 `cohort` 字段区分，建议按月份命名，例如 `student_2026_09`。
- 编号与真实身份的对应表如果确实需要，只能由测试负责人保存在受限的独立文件中；不要上传仓库，也不要写入评价、事件 metadata 或看板导出。
- 测试者可以不提供姓名、邮箱、学号或联系方式给产品。匿名编号仍属于可关联的测试数据，应按隐私数据处理。

### 在浏览器中复用

前端优先把编号保存在浏览器 `localStorage` 的 `mvp_test_anonymous_id` 中。第一次打开主页时，如果没有编号，前端会使用浏览器 `crypto` 随机源生成一个合法的 `student_` 编号并自动向 `/api/v1/test-users/identify` 登记；如果浏览器禁止存储，则只在当前页面会话内保留随机编号，不会退回到所有用户共用的固定编号。编号只用于区分测试样本，不包含姓名、手机号、邮箱或其他个人信息。

如果测试负责人需要预先分配编号，在测试者第一次打开页面前，在同一浏览器配置中设置：

```javascript
localStorage.setItem('mvp_test_anonymous_id', 'student_001');
```

然后刷新主页。测试期间不要清除该项，也不要在同一个浏览器配置中混用两名测试者；更换设备或浏览器时，应在新配置中重新设置同一个编号。重复使用同一编号可以让一个月内的事件、会话和反馈汇总到同一名匿名测试者，但不会把不同人的数据合并。

每次测试开始前核对两点：编号仍是原编号，测试批次仍是当前批次。默认批次为 `student_2026_09`；批次变化应由测试负责人统一记录，避免同一个月中随意改名。

## 邀请和执行主流程

### 邀请大学生测试

邀请内容应说明：测试时长、需要完成的操作、会记录匿名操作事件和 1 到 5 分评价、可以跳过任何问题或随时停止，以及联系人和删除请求渠道。优先邀请能覆盖不同时间安排、精力和出行条件的在校学生，但不要为了筛选而收集与产品无关的敏感信息。

给每名测试者发送：产品地址、分配的匿名编号、测试批次、完成期限和反馈入口。测试负责人另存一份最小化的分配记录，不把该记录与数据库原始事件一起共享。

### 一次完整测试

1. 在指定浏览器设置或确认匿名编号，打开主页并选择完整模式。
2. 创建会话，选择一个或多个兴趣方向，设置优先级，并填写可用时长、预算、出行方式、同行偏好、当前精力和心情等前置条件。
3. 选择快速版 5 题或深度版 30 题。逐题作答；答案会自动保存，允许返回修改、跳过问题和刷新恢复。记录测试者主动跳过某题的原因，但不要把原因写入个人身份信息。
4. 提交问卷，查看偏好画像和解释，再生成计划。核对推荐任务、匹配理由、时间线和未排入时间线但仍在推荐池中的任务。
5. 按测试者的真实意愿调整计划：修改时间、开始任务、完成任务，或跳过/替换任务。不要为了“跑通”而强迫测试者执行不愿意做的任务。
6. 在完成任务后打开该任务的“任务反馈”，选择 1 到 5 分，可选填写原因和短评，然后保存。完成后评价应尽量在任务刚完成时提交；如果没有执行任务，记录为未完成，不要伪造完成评价。
7. 若测试者跳过或替换任务，使用实际原因。系统允许的原因代码为：

   `not_interested`、`low_energy`、`not_enough_time`、`over_budget`、`location_inconvenient`、`too_difficult`、`not_matching_current_state`、`other`。

   前端提示被取消、输入不在允许列表或无法收集时会使用 `other`。测试负责人应在独立测试日志中补充“跳过/替换发生在什么步骤”和“是否是产品阻塞”，不要写姓名、联系方式或其他身份细节。

8. 测试结束后记录匿名编号、日期、完成到的最后一步、是否完成反馈、主要阻塞和下一步建议。记录应使用匿名编号，不使用真实姓名。

## 管理员看板

### 环境变量和地址

后端启动前设置：

```powershell
$env:SESSION_DATABASE_URL = 'postgresql://postgres:<password>@127.0.0.1:5433/free_time_agent'
$env:ADMIN_METRICS_USERNAME = '<admin-username>'
$env:ADMIN_METRICS_PASSWORD = '<strong-password>'
```

启动时会运行可重复的迁移，并在数据库中初始化单一管理员账号。管理员密码在数据库中以 scrypt 哈希保存；不要把明文密码写入 README、脚本、提交记录或聊天记录。已经初始化过管理员后，改变环境变量不会创建第二个管理员；需要由数据库负责人按受控流程处理账号变更。

本地静态前端运行后访问：

```text
http://127.0.0.1:5173/admin.html
```

部署到同域名时使用 `https://<your-domain>/admin.html`。看板页面与普通用户主页隔离，页面只请求管理员登录、退出和聚合指标接口。

### 登录、筛选和退出

1. 打开看板，填写管理员账号和密码并登录。登录成功后浏览器暂存短期 bearer token；不要复制或分享 token。
2. 在开始日期、结束日期、测试批次、匿名编号和任务分类中输入筛选条件，点击“刷新指标”。日期范围按 UTC 日期边界处理，结束日期包含当天。
3. 检查流程漏斗、推荐效果、精力与推荐关系、跳过与替换原因、原因补充说明、流程错误和匿名用户明细。明细只显示匿名编号、批次、行为计数和限制为 500 字的补充说明，不显示姓名、邮箱等个人身份字段。
4. 离开看板时点击“退出”。退出会撤销当前 token；关闭浏览器或发现 token 泄露时也应退出并通知管理员。

所有管理员指标路由都要求 bearer 认证，认证在筛选条件解析前执行。缺少或无效认证应返回 401；不能用错误的日期或分类筛选绕过登录。

## 指标口径

看板提供八组接口：`summary`、`funnel`、`recommendations`、`energy-recommendations`、`reasons`、`reason-details`、`errors`、`user-detail`。事件时间使用 `occurred_at`，评价时间使用 `created_at`。

| 指标 | 口径 |
| --- | --- |
| `summary.user_count` | 筛选范围内出现过任一测试事件的去重匿名编号数。 |
| `summary.session_count` | 有 `session_created` 事件且 `session_id` 非空的去重会话数。 |
| `summary.full_flow_success_rate` | 同时有 `session_created` 和 `feedback_submitted` 的去重会话数 ÷ `session_count`，百分比，最多 100%。评价事件必须属于已创建会话。 |
| `summary.average_rating` | 筛选后的测试任务评价平均分；同一 `plan_item_id` 只计一条当前评价。无数据时为 0。 |
| `summary.replacement_rate` | `task_replaced` 事件数 ÷ `recommendations_viewed` 事件数，百分比。 |
| `summary.skip_rate` | `task_skipped` 事件数 ÷ `recommendations_viewed` 事件数，百分比。 |
| `funnel` | 按事件发生次数返回 `session_created`、`questionnaire_completed`、`recommendations_viewed`、`task_started`、`task_completed`、`feedback_submitted` 六个步骤；不会把每一步误当成去重用户数。 |
| `recommendations` | 按 `task_category` 汇总推荐查看次数、评价平均分、替换率和跳过率。评价通过该计划项最近一次带分类的事件映射到分类；没有分类事件的评价归入 `unknown`。 |
| `energy-recommendations` | 按事件 metadata 中的 `energy_level` 和 `task_category` 汇总推荐查看次数、评价平均分、替换率和跳过率；只使用已上报的精力值，不重新计算推荐结果；最多返回 100 个分类组合。 |
| `reasons` | 所有带 `reason_code` 的跳过/替换事件按原因代码计数，并按数量降序展示。 |
| `reason-details` | 返回最近 100 条带原因代码和非空 `reason_detail` 的匿名事件，文本服务端限制为 500 字并进行 HTML 转义；只展示匿名编号、原因代码、说明和时间。 |
| `errors` | `flow_error` 事件 metadata 中的 `error_code` 计数，最多返回 100 个代码；缺少代码归为 `unknown`。 |
| `user-detail` | 按 `anonymous_id`（可选）返回匿名编号、批次、事件/会话/完成/跳过/替换计数和平均评分；最多返回 500 个匿名用户；不返回姓名、联系方式或其他个人身份字段。 |

日期、`cohort` 和 `anonymous_id` 会作用于相应事件或评价记录；`task_category` 会筛选带分类的事件，并对评价使用计划项的分类映射。指标是匿名聚合数据，不能反推出完成率等于独立用户数。

## 一个月测试周期

建议把一个月分成“招募、首轮完成、复测/跟进、总结”四周，但以实际测试安排为准。每次测试在受限的测试日志中记录：匿名编号、批次、日期、完成到的主流程步骤、是否提交完成后评价、跳过/替换原因代码、产品阻塞和后续动作。日志不要复制原始评价全文，不要加入姓名或联系方式。

管理员每周使用相同的 `cohort` 和日期筛选查看趋势，必要时再按匿名编号定位单名测试者的匿名记录。导出或截图只保留汇总结果；共享前去除匿名编号筛选结果和可能泄露测试者行为的细节。测试周期结束后冻结汇总口径，注明筛选日期和时区，避免后续补写事件改变历史结论。

### 隐私、保留和删除

- 测试遥测只应包含匿名编号、会话/计划项 ID、允许的事件、原因代码、最多 500 字的 `reason_detail`、有限 metadata 和 1 到 5 分评价；不要发送姓名、邮箱、学号、精确住址或自由文本中的身份信息。
- 匿名编号和真实身份分配表必须分开保存，并限制访问。`comment` 仅用于短评，最长 500 字符；测试负责人应先检查内容再导出。
- 匿名观测数据默认保留 90 天，截止时间按 `test_users.last_seen_at < 当前时间 - 90 天` 判断。90 天清理不会自动由后台调度；管理员应在受控维护窗口打开看板并点击“清理超过 90 天的数据”，或使用已认证的 `POST /api/v1/admin/test-observations/cleanup`。接口返回本次删除的匿名用户数量，重复运行是安全的。
- 删除单个测试者时，管理员先在看板输入匿名编号并确认，或调用已认证的 `DELETE /api/v1/admin/test-users/{anonymous_id}`。这两个操作只删除 `test_users` 及其级联的 `test_events`、`task_test_feedback` 观测数据，不删除业务 `sessions`、`plans`、`plan_items` 或正常业务反馈；管理员会话也不会被清理操作删除。
- 管理员删除操作复用现有 bearer 管理员认证；未登录或令牌失效时不会解析或执行删除。操作后可按匿名编号刷新看板核对记录已消失，只保留无法回溯到个人的汇总结论。
- 测试者可以要求停止参与或删除其匿名记录。测试负责人先确认匿名编号，再从独立分配表移除对应关系，完成数据库清理后删除本地测试日志中的该编号记录。

## 安全边界

观察失败不会阻塞会话、问卷、推荐、排程或执行主流程；看板故障也不应让测试者重复提交业务操作。管理员接口必须保持认证，公网部署必须使用 HTTPS、限制 CORS 来源并通过密钥管理注入环境变量。不要在测试文档、浏览器截图或 issue 中粘贴管理员密码、bearer token、数据库连接串或含个人信息的评价。

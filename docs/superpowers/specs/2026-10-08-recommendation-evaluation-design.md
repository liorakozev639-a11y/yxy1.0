# 推荐任务离线评测集设计

## 目标与边界

为当前规则任务库建立 50 个固定、可重复运行的评测场景：完整模式 30 个，极简模式 20 个。评测硬约束、任务重复和理由中的可核验陈述，另提供 10 条理由的人工复核表。评测发现的推荐缺陷应保存修复前结果、修复并用相同场景复测。本阶段不调用真实模型、API 或 PostgreSQL，不改变产品交互。

## 组件与数据流

- `data/recommendation_evaluation_cases.json`：50 个显式场景；包含模式、时长、精力、完整模式的预算、出行、同行、分类及可选天气/时间段/心情，并标记预期空结果和连续替换轮数。
- `recommendation_evaluation.py`：读取并校验场景；使用现有 `TaskBankProvider(TaskRepository())` 获取候选。完整模式使用 `is_full_eligible()` 后调用 `recommend_tasks()`；极简模式调用 `rank_quick()`。输出机器可读 JSON 汇总及逐场景结果，并为人工复核生成 CSV。
- `tests/test_recommendation_evaluation.py`：验证 50 个 ID 唯一、30/20 分布、场景格式、评分器分母、空结果、排重与理由矛盾检查。
- `docs/recommendation-evaluation.md`：中文运行说明、指标定义、人工复核办法、基线与修复后报告的读取方式。
- `reports/recommendation-evaluation/`：保存首次基线和最终结果，供版本对比。

数据流：场景 -> 候选生成与硬筛选 -> 排序/推荐 -> 逐任务核验 -> 分模式与总体汇总 -> JSON 报告和人工复核 CSV。报告须保留原始场景 ID、任务 ID、发现的失败原因，便于定位。

## 指标口径

- 约束符合率：符合全部硬条件的返回任务数 / 返回任务总数。明确标记预期空结果的场景，空结果算一个合格机会；错误地返回空结果算一个失败机会。精力属于排序偏好，不当作硬约束。
- 重复率：同次结果重复 ID 数及连续替换时重现先前排除 ID 数 / 两种检查对应的返回任务数。候选耗尽时可返回空，不为凑数放宽条件。
- 自动理由一致率：可核对且成立的声明数 / 所有被检查的声明数。检查类别、时长、预算、出行、同行、精力标签和相应理由；缺失理由算失败。不被规则覆盖的主观措辞不进入自动准确率。
- 人工理由复核：从两种模式抽取共 10 条非空结果，保留理由原文和任务信息，人工填写贴切与否及原因；未填前不发布“人工准确率”。
- 报告既列总体也列两种模式的分子、分母和比率，并记录空结果、每轮替换的任务 ID 及失败详情。零分母时比率为 `null`，不伪装为 100%。

## 场景覆盖与异常

50 个场景应覆盖低精力、低预算、只在家、10–20 分钟、时间/预算/出行/同行的组合、无候选、多分类及连续替换。完整模式至少 30 个，极简模式至少 20 个。若输入格式不合法、任务库变空、理由缺失或评测代码异常，报告明确列出错误并返回非零退出码；不得静默跳过该场景。

修复推荐逻辑前先保存基线 JSON；随后针对真实失败补测试、做最小修复并生成最终 JSON。只修复本评测明确揭示的推荐错误，保持既有 API 响应字段和其他业务模块不变。

## 验收

用仓库 Python 环境一条命令运行离线评测，无数据库或模型密钥。场景数严格为 50，30/20 分布。自动化测试验证分母、空结果、重复和理由判定。最后运行现有推荐相关测试和前端相关测试；报告中明确自动一致率与待人工复核的边界。

# 极简模式验收清单

本期极简模式使用现有任务库。AI 候选来源只预留接口，没有接入 DeepSeek，也不会消耗模型 Token。完整模式中的“快速版问卷”与首页“极简模式”是两个不同概念。

## 1. 启动前检查

1. 启动 PostgreSQL，并确认 `SESSION_DATABASE_URL` 指向**测试数据库**。运行 `pg_isready -h 127.0.0.1 -p <测试端口>`，预期显示 `accepting connections`。不要把数据库密码写入仓库或测试截图。
2. 在仓库根目录运行后端：`python -m uvicorn main:app --host 127.0.0.1 --port 8000`。打开 `http://127.0.0.1:8000/health` 和 `http://127.0.0.1:8000/api/v1/health/database`，两个响应的 `data.status` 均应为 `ok`。
3. 在另一个终端、仓库根目录运行前端：`python -m http.server 5173 --bind 127.0.0.1 --directory frontend`。打开 `http://127.0.0.1:5173/`，应看到“马上找件小事”和“认真安排空闲”两个入口。

## 2. 极简主流程

1. 点击“马上找件小事”。预期只需填写分钟数和当前精力，无分类、问卷、预算或地点表单；后端仅在点击生成时创建独立极简会话。
2. 输入 `15` 分钟，选择“有点累”，点击“看看现在能做什么”。预期出现一个首选任务，包含任务名、建议分钟数、推荐原因和“现在先做”；任务不超过 15 分钟、零预算、居家、可独自完成。后端生成一条 `quick_recommendation_runs` 记录，不创建计划项。
3. 点击“查看更多”。预期只出现当前轮次的其他合格任务，不与首选任务重复；点击其中一个后它成为首选。
4. 点击“不喜欢”。预期当前任务消失，下一项前移；再次生成时刚否定的任务仍不出现。后端保存 `disliked` 反馈，且同轮同任务重复反馈只保留最新一次。
5. 点击“喜欢”。预期界面显示“已喜欢”；用户历史的实际完成数**不增加**，不会触发任务开始、计时、截止或完成接口。
6. 点击“直接休息”。预期显示休息状态，而非失败或未完成。刷新页面后仍显示休息；后端只记录中性的 `rest_selected`，不降低任务偏好权重。

## 3. 边界与恢复

1. 把时长改为 `1` 分钟并生成。预期“当前条件下暂无合适建议”，仍可修改时长或直接休息；后端不会放宽预算、出行或同行限制来凑数。
2. 输入 `0`、负数或超过 `480` 分钟，或不选精力。预期页面阻止无效请求；直接调用接口应收到 `422`，不会生成推荐轮次。
3. 生成后刷新页面。预期仍在极简模式，输入草稿和最近一轮推荐恢复；之前“不喜欢”的任务不重新出现。
4. 在浏览器开发者工具中模拟断网，再点击生成或反馈。预期显示错误和“重试”，保留原输入/任务，不展示虚假的成功；恢复网络后点击“重试”可继续。
5. 在 375px、768px 和桌面宽度检查按钮、任务标题、候选列表。预期没有横向滚动或内容遮挡。

## 4. 模式切换与完整流程

1. 从极简模式点击“完整模式”。预期看到现有分类选择页；继续填写偏好、选择快速版或深度版问卷、提交问卷、查看偏好画像并生成计划。极简模式不冒充已提交问卷。
2. 在完整模式开始/完成一个计划任务并提交评分。预期计划状态和完成数按原逻辑更新。
3. 再切回“极简模式”。预期原极简输入与最近建议保留；两个模式的 `session_id` 不相同，但匿名 `user_id` 相同。
4. 再回完整模式。预期原问卷及计划状态还在。极简“喜欢”不算完成，极简“不喜欢”可影响同一用户后续完整模式推荐。

## 5. 自动化回归

仅在独立测试库中设置 `SESSION_DATABASE_URL` 后运行：

```powershell
python -m unittest tests.test_quick_recommendation_api tests.test_quick_full_flow -v
python -m unittest discover -s tests -p 'test_*.py'
node --test (Get-ChildItem tests -Filter '*.test.js').FullName
```

预期三条命令退出码均为 `0`。数据库测试会创建临时会话；不要让这些命令指向正在使用的正式数据库。
